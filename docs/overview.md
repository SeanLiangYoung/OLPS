# Open LPS 是什么（白话说明）

这份文档用日常语言说明：系统是什么、谁在用、页面怎么分、广告页怎么走、后台要能看到什么、和旧 LPS 什么关系。  
细节见其它文档；先读懂这一份即可把需求说清楚。

---

## 一、产品是什么

做一个**专门服务落地页的内容管理系统**：支持**多个租户**；用 SSO 登录后，**先选当前租户**，之后都在这个租户下管站；需要时可以切换租户。

使用方是熟悉站点能力与优化能力的**运营**。日常工作在后台的**模块化页面**里完成：页面、生成、引导图、发布、广告、分析、报告、询盘、站点配置等，每块能力有稳定入口与固定路径。  
本系统面向运营与组织，不把对话当成主交互。

可以把它想成：像 WordPress 那样专注「把站管好」，同时带上企业/租户边界，并特别擅长广告承接、知识库建站和「千人千面」引导页。

---

## 二、登录与租户

1. **SSO 登录**（账号 token 用于请求各服务）。  
2. **登录后第一时间选择当前租户**（只有一个也可直接进入，当前租户仍要明确）。  
3. **后续操作都在所选租户下**（站点、页面、生成、发布、选知识库、接广告、询盘等）。  
4. **允许切换租户**；切换后工作上下文换到新租户，不与上一租户混用。  

详见 [tenant-context.md](tenant-context.md)。

---

## 三、刻意不做的事

- 不把对话当成配置系统或管站的主路径。  
- 不把旧系统里难用、绕的壳再搬一遍；能复用的生成能力、校验规则、已验证技能、租户/SSO 继续用。  
- 不在聊天里猜测当前租户 ID。

---

## 四、一个站里有三类页面

所有给访客看的页面分成三类，并且**可以互相跳转**。

### 1. 通用站页

网站的骨架：首页、产品列表、关于我们、联系我们等。相对稳定，也是搜索引擎常看的门面。

### 2. 内容页

具体的产品详情、案例、博客文章等。条目较多；可从列表进入，也可从广告页链过来。

### 3. 广告承接页（千人千面）

专门接广告流量：按关键词意图分屏讲清楚，再用引导选项带访客走完旅程，最后落到转化（询盘等）。

三类在后台要**一眼分得清**，也能看清**哪些已发布、哪些还是草稿**。

---

## 五、广告页怎么设计

### 多个相关关键词共用一页

运营选定一组相关搜索词（例如两三个到七八个）。  
**屏里的内容是这一页共用的一套**。每个关键词有自己的起始屏和自己的公开地址，打开后进入这套屏，沿引导走到同一块转化屏。不会按关键词各复制一套内容屏。

### 整页只有一个转化终点

所有路径最后汇到**同一个重点转化屏**。旅程要**完整、清楚**：从任意关键词入口出发，都能走到转化。转化动作以**询盘**为主。

### 引导关系要看得见、改得了

屏与屏之间怎么跳，不能是黑盒。后台要能看到：

- 哪个关键词对应哪块起始屏；  
- 有哪些屏；  
- **跳转关系图**（点了哪个选项去哪一屏）；  
- 校验结果（能否走到转化、是否成环等）。

运营可以**改选项文案、改跳到哪、加减选项**，改完要能检查是否仍合理。  
「重新生成一遍」可以当辅助，不能是唯一改法。

### 尽量别让访客反复看到同一屏

路径要往前走、往转化收。访客点选过程中，系统应尽量不让「又回到刚才那一屏」的选项继续出现。  
跨关键词跳转仍然允许，目标应是尚未走过的屏，整体仍朝 CTA 前进。

## 六、后台（运营主界面）

进入后台前：已 SSO 登录，且已选定**当前租户**（顶栏可切换）。

后台按模块展示能力与链路：

1. **页面**：按三类看清全部页面与发布状态。  
2. **页面详情**：改内容、预览、发布或下线；广告页额外提供引导关系图编辑。  
3. **生成 / 优化**：在固定流程里选知识库、发起生成或改写；依赖知识的步骤必须已选库。  
4. **询盘**：查看、筛选、处理访客询盘；邮件通知与重发。  
5. **广告 / 分析**：连接并调整 Google 广告、分析账户。  
6. **报告**：诊断公开页或本站页，再指导修改。  
7. **站点设置**：语言、地图、WhatsApp agent、站内行为采集、共用屏块数上限、发布相关等。  
   不带：品牌与 Logo、巡检与优化策略、Guide「文档流/悬浮」二选一（**只做悬浮**）、企业知识库设置区块。  
   详见 [settings-scope.md](settings-scope.md)。  
8. **发布之后**：访客能打开；自动维护**站点地图**。

预览可切换电脑 / 平板 / 手机宽度。

能力在服务端只实现一份。后台模块通过 HTTP API 调用；命令行与外部系统也调同一套 API（账号 token + 当前租户）。已验证的技能与 CLI 可挂在生成等固定流程背后，由模块页触发，不单独做成对话工作台。

---

## 七、站点能力：默认带字段，开关由运营配置

内容模型与发布管道从一开始就带上这些能力所需的字段与结构。是否启用、启用哪些语言、地图钥匙、WhatsApp 等，由运营在站点设置里配置：

| 能力 | 要求 |
|------|------|
| **搜索引擎友好** | 每页有标题与摘要等；发布页可被抓取理解；广告分屏也要有可读主内容 |
| **站点地图** | 已发布页面自动进入站点地图 |
| **多语言** | 运营配置站点语言列表与默认语言；各语言内容、地址、广告引导文案分开维护 |
| **地图** | 运营配置是否使用及 Google Maps 相关钥匙；页面可放地图块；无钥匙时至少地址文字与外链 |
| **WhatsApp agent** | 运营配置是否启用及号码 / 入口等；启用后发布页按配置挂上访客侧入口 |
| **三端适配** | 电脑、平板、手机默认都能用 |

细则见 [platform-defaults.md](platform-defaults.md)。

## 八、保留的专项能力

- 基于**知识库**生成和改写页面（流程中选择知识库）  
- **诊断 / 报告**  
- **千人千面**广告承接  
- **询盘**（表单提交、后台列表与处理、邮件通知与重发）  
- **Google 广告 / 分析**（运营在后台连接并调整）  
- **预览 → 发布**

## 九、和旧 LPS 的关系

| 继续用 | 放下 |
|--------|------|
| 生成、引导校验、知识库、评分、模型调用、询盘对接等已跑通的本事 | 以对话为壳的工作台用法 |
| 已验证技能、规格包（尽量不改规格包，只读复用） | 品牌 Logo 设置、巡检策略、Guide 文档流、企业知识库设置区块 |
| 能力经 API / CLI 暴露的同一份实现 | 平行重写一套技能或规格 |

新项目做的是：产品讲清楚、后台模块好用、当前租户下把站管清楚；底下能复用的就复用。

## 十、当前要先跑通的一条路

1. SSO 登录 → **选择当前租户**（并可切换）。  
2. 在该租户下有站点；至少有一个通用页、一个内容页、一个广告承接页。  
3. 后台能按三类看见它们，能看见谁已发布。  
4. 广告页的跳转关系能看见、能改一处并生效。  
5. 发布后访客打得开；有基础的搜索信息；有站点地图；手机宽度下也能看。  
6. 运营能在模块页发起一次生成或改写并完成发布。

---

## 十一、谁负责什么

- **账号持有人**：SSO 登录、选租户 / 切换租户。  
- **运营**：在当前租户后台完成页面、引导图、配置、询盘、广告/分析、报告、发布。  
- **访客**：打开已发布页面；广告来的走关键词起始屏与悬浮引导；可提交询盘；可按配置使用 WhatsApp 入口。  
- **搜索引擎 / 优化**：读页面信息与站点地图。  
- **外部系统**：直接调正式接口。

---

## 十二、已拍板的细则

### 1. 广告地址：一词一个独立地址

每个关键词对应一个独立公开地址。访客从哪个词的广告进来，就打开那个词自己的地址，并进入该词的起始屏。  
后台仍可按「相关词一组」一起策划和生成；对外投放是一词一址。

### 2. 共用屏块数上限：默认 20，且必须可配置

20 限制的是**这一张广告承接页上、全体关键词共用的那一套屏一共多少块**。  
关键词个数、一词一址的地址个数，不靠这个数字去卡。  
默认 20；站点或该页设置可改。

### 3. 浏览器「后退」：重新开放已经看过的屏

访客按浏览器后退回到某一屏时，视为回到那一时刻：  
**从当前屏往后已经走过的「看过」记录要放开**，已经看过的屏可以再次作为向前选项出现。

---

## 十三、默认模型

页面生成、引导规划、文案、翻译、报告等业务模型默认使用 **DeepSeek V4**。  
接入名以环境配置为准（常见为 `deepseek-v4-pro`）；站点或部署环境可改默认模型。
