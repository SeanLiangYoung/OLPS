# 存储：去掉 Redis，统一用 PostgreSQL

> 对照旧 LPS 源码后的结论。  
> 旧系统里站点内容、版本、任务状态已经在 PostgreSQL。Redis 只承担排队通知、会话、短时密钥。

---

## 旧 LPS 里 Redis 实际在干什么

| 用途 | 谁在用 | 里面放什么 | 真正的业务数据在哪 |
|------|--------|------------|--------------------|
| **任务排队** | BullMQ（生成、设置类任务、V2 任务、定期巡检） | 很薄的通知：任务编号、租户、关联号 | **PostgreSQL**（任务表 + 发件箱 Outbox）。代码写明：Redis 不得携带权威任务内容 |
| **登录会话** | 后台中间层（Workbench BFF） | 加密后的会话（开发环境也可改成内存） | 仅表示登录态 |
| **短时凭证保险柜** | 发布等相关凭据 | 加密后的临时密钥，到期删除 | 生产环境目前强制要连 Redis 才能开这个保险柜 |

---

## open-lps 做法

**不再单独部署 Redis。**

| 旧用途 | open-lps 做法 |
|--------|----------------|
| 任务排队 | 继续用 PostgreSQL 里的任务表 / 发件箱当队列。后台写入待执行行；工作进程用数据库锁领取（例如 `SKIP LOCKED`），或选用基于 PostgreSQL 的队列库 |
| 登录会话 | 本系统注册/登录；会话 token 摘要与过期时间存 PostgreSQL，支持退出撤销 |
| 短时凭证 | 必须暂存时：PostgreSQL 加密列 + 过期时间，到期清理 |
| 站点 / 页面 / 引导 / 发布记录 | 本来就在 PostgreSQL，保持唯一真源 |

生成、校验、技能仍复用。变的是**怎么叫醒工作进程**：从「Redis 里的 BullMQ」改成「PostgreSQL 里的待执行任务」。

不要把 Redis 的键值用法原样搬进 PostgreSQL 当通用缓存。业务真源本来就在表里。
