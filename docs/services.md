# 跑起来要哪些进程

旧 LPS 的 Compose 里长期挂着很多容器。open-lps 只留真正一直要干活的进程。一次性动作并进主服务启动，不单独做镜像。

## 旧 LPS 实际有什么

| 名字 | 启动后还在不在 | 干什么 |
|------|----------------|--------|
| postgres | 一直在 | 数据库 |
| redis | 一直在 | 排队、会话、短时密钥。open-lps **不要** |
| migrate | 跑完就退出 | 把数据库结构补到当前版本 |
| artifacts-init | 跑完就退出 | 建发布目录并改所有者 |
| api | 一直在 | 业务接口 |
| generator-worker | 一直在 | 消费生成队列 |
| lps-runtime | 一直在 | 预览和已发布页 |
| agent-runtime | 一直在 | 对话运行时与内部 token |
| agent-sandbox-image | 默认不启动 | 沙箱镜像 |
| workbench-bff | 一直在 | 浏览器与接口之间的中间层 |
| workbench | 一直在 | 前端页面 |
| nginx（生产编排里） | 部署时才有 | 对外转发 |

`migrate` 和 `artifacts-init` 都是准备步骤，跑完不重启。

## open-lps 留哪些

日常开发只跑：

1. **PostgreSQL**  
2. **一个后端进程**：启动时先补数据库结构、准备发布目录，然后提供接口，并在同一进程里领取生成任务；预览和已发布页面也由它给出。  
3. **管理端页面**（开发时的前端；上线可以是静态文件）

登录用现有 SSO。浏览器、命令行、外部系统都拿**这个账号的 token + 当前租户**直接调这个后端。

## 不单独存在的

| 旧东西 | 决定 |
|--------|------|
| **BFF** | 不要。命令行本来就是拿 SSO token 直接调接口。BFF 再签发短时内部 token，密钥或能力名单对不上就 401，且不增加业务能力。 |
| Redis | 不要。见 [storage.md](storage.md) |
| 独立的 migrate / artifacts-init 容器 | 不要。并进后端启动 |
| 独立的生成工人、页面运行时、对话运行时、沙箱镜像 | 不要各做一个镜像。生成由后端进程领取；页面由后端给出；技能经 CLI 调同一后端 |
| 服务之间互相换 token | 不要。调用方用登录拿到的 token |

生成任务由这同一个后端进程领取，连同一份 PostgreSQL。
